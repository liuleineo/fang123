# 2026-10-14 自建用户访问统计（P0）

## 目标

给网站做访问统计。结论是**自建轻量埋点**而不是接第三方：
项目已有多端（web/admin/小程序/App）和完整的用户体系，第三方 SaaS 拿不到 `user_id`，
无法回答"哪个渠道来的人最终买了会员"这类问题，且多端 SDK 口径不统一。自建一套接口各端共用，
后续能直接和 `member_user`、`task_pay_log` 做转化分析。

P0 范围：PV/UV/会话/新访客/实时在线、日趋势、平台分布、热门页面 TOP20。

## 架构

```
web(埋点) ──POST /api/public/visit/report──┐
小程序/App（后续接入同一接口）────────────┤─→ 内存队列 → 单线程批量写 → visit_event（明细）
                                          │                              ↓ 每小时/启动时聚合
管理端 ──GET /api/admin/visit/dashboard───┴──────── visit_stat_daily（日报） ←─┘
```

**两层数据模型**是核心：明细只追加、报表只查日报，明细再大也不影响管理端响应；
明细保留 90 天后自动清理，历史报表不受影响。

## 关键设计决策

1. **写入与业务解耦**：上报接口只入队（有界队列 2 万条），独立线程按 500 条 / 1 秒批量写库；
   队列打满时丢弃并告警，绝不阻塞业务请求。关闭时把剩余数据写完，避免重启丢数据。
2. **幂等聚合**：所有聚合都是 `INSERT ... SELECT ... ON DUPLICATE KEY UPDATE`，
   重跑只覆盖不累加，所以当天数据可以每小时滚动刷新，也允许手动补数。
3. **UV 去重**：登录后按 `u:{userId}`、匿名按 `d:{deviceId}` 写入 `visitor_key`，UV 直接
   `COUNT(DISTINCT visitor_key)`，避免"登录前后算两个人"（同一人跨登录态仍会算两次，属 P0 可接受偏差）。
4. **启动回补 7 天**：服务停机期间定时任务不跑，`ApplicationReadyEvent` 会回补最近 7 天日报，
   避免图表出现空洞；更早的日期可用 `POST /api/admin/visit/aggregate?date=yyyy-MM-dd` 补。
5. **爬虫过滤**：UA 命中 `bot/spider/crawl/curl/wget/headless/lighthouse` 直接丢弃；
   UA 为空也丢弃（脚本上报）。爬虫刷 PV 是最常见的统计失真来源。
6. **客户端时间校正**：上报带 `ts`，与服务器时间偏差超过 12 小时则回落到服务端时间，防止改系统时间污染趋势。
7. **隐私**：只存 IP 的 MD5、UA 只存"系统/浏览器"两位摘要、`page_title` 截断，不落完整指纹。
8. **路由归一化**：前端把 `/loupans/123` 归一成 `/loupans/:id`，否则 TOP 页面会被动态 id 撑爆。
9. **渠道判定**：优先 `utm_source`，其次 referrer 域名（微信/搜索引擎/站内），会话内跳转记为 internal，
   结果缓存在 `sessionStorage`，避免内部跳转反复解析。
10. **前端默认不上报**：只有生产构建（或显式 `VITE_VISIT_TRACK=true`）才上报，本地开发不污染线上数据。

## 验证

后端在本地 8090 启动，实测结果：

```
POST /api/public/visit/report （Chrome UA）      → 200，1~3 秒内异步落库
POST /api/public/visit/report （curl UA）        → 200 但被丢弃（爬虫过滤生效）
POST /api/public/visit/report （events 为空）     → 200，无副作用
落库校验：channel=search（由 baidu referrer 推导）、ua_brief=Windows/Chrome、duration=2500 ✓

启动回补：日志 "访问统计启动回补完成：2026-10-08 ~ 2026-10-14"
日报校验：10-13 PV2/UV2/新访客1、10-14 PV3/UV3/新访客2（与造的数据一致）✓

mvn test -Dtest='VisitStat*Test' → Tests run: 3, Failures: 0, Errors: 0
  - 聚合 + 看板：结构完整、趋势按天补齐 7 天、TOP 页面 PV 正确
  - 上报接口匿名可访问
  - 看板接口未登录 4xx、带管理员 token 返回完整结构
```

## 部署注意

1. **生产库需要执行新表 DDL**（`schema.sql` 里新增的两张表，或直接跑该片段）。
2. 后端需重新部署（新增接口），web 与 admin 需发布新 `dist`。
3. Nginx 无需改动：`/api` 已反代到后端，埋点走同一前缀。
4. 管理端入口：侧边栏「仪表盘 → 访问统计」。
