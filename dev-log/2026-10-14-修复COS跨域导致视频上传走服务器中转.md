# 2026-10-14 修复 COS 桶跨域不匹配：视频上传不再经过服务器

## 现象

`https://hangfang123.com/admin/medias` 上传视频，进度依旧卡住、耗时很长，实际仍走
"浏览器 → 服务器 → COS" 两段串行（`POST /api/admin/medias/upload`），
之前做的浏览器直传没有生效。

## 根因

直传代码本身没问题，是**桶跨域白名单不匹配**：

```
$ curl -X OPTIONS https://neoimage-1251198067.cos.ap-shanghai.myqcloud.com/media/loupan/x.mp4 \
    -H "Origin: https://hangfang123.com" -H "Access-Control-Request-Method: PUT"
HTTP/1.1 403 Forbidden
<Code>AccessForbidden</Code>
CORSResponse: This CORS request is not allowed ...
```

桶上已有规则：

```
origins=[https://*.gongziyu.com, https://*.niurouzhou.com, https://*.hangfang123.com]
methods=[PUT, GET, POST]
```

COS 的 origin 通配符 `https://*.hangfang123.com` **不匹配裸域 `https://hangfang123.com`**
（只匹配 `https://任意子域.hangfang123.com`）。而管理端就是裸域访问，
所以 OPTIONS 预检 403 → 前端 `uploadDirectToCos()` 抛错 → 静默降级到服务器中转。
降级只打了 `console.warn`，页面上完全看不出来，属于"静默失败"。

## 改动

### 1. 桶 CORS（已在线修复，立即生效）

在原有规则上**补齐**（不覆盖其他来源）：

```
origins=[https://*.gongziyu.com, https://*.niurouzhou.com, https://*.hangfang123.com,
         https://hangfang123.com, http://localhost:3000, http://127.0.0.1:3000,
         http://localhost:5173, http://127.0.0.1:5173]
methods=[PUT, GET, POST, HEAD]     # 原缺 HEAD
maxAge=3600                        # 原为 0，每次上传都要重新预检
```

### 2. 后端（防回归，需部署重启才生效）

- `backend/src/main/java/com/fang123/config/CosProperties.java`
  - 新增 `autoCors`（默认 true）与 `corsOrigins`（列表）。
- `backend/src/main/java/com/fang123/service/CosService.java`
  - 新增常量 `REQUIRED_CORS_METHODS`（PUT/GET/HEAD/POST）。
  - 新增 `syncBucketCors()`，在 `@PostConstruct init()` 末尾调用：
    - 读取桶现有规则，**幂等补齐**缺失的 origin 与 method，不动其他来源；
    - 桶上没有规则时创建一条默认规则；
    - 凭证无 `PutBucketCORS` 权限或网络异常时只 `log.warn`，不阻塞启动。
  - 目的：换桶/重建桶/新环境上线后，不会再因为漏配裸域而静默回退到服务器中转。
- `application-dev.yml` / `application-prod.yml`：`cos` 下新增 `auto-cors: true`
  与 `cors-origins`（dev 含 `http://localhost:3000`，prod 含根域与 `www` 域）。

### 3. 前端 `admin/src/views/LoupanMediaManage.vue`

- 「批量新建素材」原本也走服务器中转，改为 `uploadDirectToCos()` 直传，
  失败才回退中转（复用已有降级通道）。
- 单个上传的降级分支增加 `MessagePlugin.warning('直传云存储失败，已切换到服务器中转上传（请检查 COS 桶跨域配置）')`，
  避免再次出现"悄悄走中转、没人发现"。

## 验证（线上桶实测）

```
OPTIONS 预检 (Origin: https://hangfang123.com) : 200   # 修复前 403
预签名 PUT 直传                                 : 200
回读 GET                                        : 200
```

预签名 URL 由 COS SDK 按 `CosService.presignPut()` 同样的逻辑（`Content-Type` 绑定 + 600s 有效期）生成；
测试对象 `media/loupan/_probe_direct.mp4` 已删除。

`POST /api/admin/medias/presign` 线上返回 401（未登录），说明接口已部署，无需再发版后端。
