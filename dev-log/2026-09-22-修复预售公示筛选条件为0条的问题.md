# 2026-09-22 修复"预售公示"板块始终 0 条的问题

## 现象

首页"预售公示"板块角标与列表始终为 0，但库中确有处于公示期的预售证。

## 排查过程

1. 查看库中 `loupan_presale_permit` 有效数据（`deleted=0` 且 `loupan_id` 非空）仅 3 条：

   | id | loupan_id | 公示日期 | 核发日期 | 说明 |
   | --- | --- | --- | --- | --- |
   | 26467 | 2 | 2026-09-21 | 2026-09-23 | 公示中 |
   | 26463 | 3 | 2026-09-15 | 2026-09-23 | 公示中（所属楼盘已删除） |
   | 1 | 1 | 2026-09-16 | 2026-09-20 | 已核发（属"最新开盘"） |

   另有 id=26465（公示 2026-09-22 / 核发 2026-09-30）但 `deleted=1`，被逻辑删除。

2. 当前代码条件为 `issue_date < today AND publicity_date >= today`（今天 09-22）：
   核发日期 09-23 不小于今天，故两条公示中数据全部被排除 → 恒为 0。**该条件方向写反了**。

## 修改

`backend/src/main/java/com/fang123/controller/LoupanSpotlightController.java`

```java
/** 预售公示：正在公示期内（公示日期已开始 且 核发日期尚未到） */
private List<LoupanPresalePermit> presalePermits(LocalDate today) {
    return permitService.list(new LambdaQueryWrapper<LoupanPresalePermit>()
            .isNotNull(LoupanPresalePermit::getLoupanId)
            .isNotNull(LoupanPresalePermit::getPublicityDate)
            .le(LoupanPresalePermit::getPublicityDate, today)   // 公示已开始
            .isNotNull(LoupanPresalePermit::getIssueDate)
            .gt(LoupanPresalePermit::getIssueDate, today)       // 尚未核发
            .apply("publicity_date < issue_date")
            .orderByDesc(LoupanPresalePermit::getPublicityDate) // 最近开始公示的在前
            .orderByDesc(LoupanPresalePermit::getId));
}
```

同时更新类注释：预售公示 = 公示日期 <= 今天 < 核发日期。

## 结果（重新打包 + 重启后）

- SQL：`... publicity_date <= ? AND issue_date > ? AND publicity_date < issue_date ORDER BY publicity_date DESC,id DESC`
- `GET /api/public/loupan-spotlight/counts` → `{"opening":1,"presale":1}`
- `GET /api/public/loupan-spotlight?type=presale` → 1 条：`滨江兴耀.沐青云`（钱塘区，公示 2026-09-21，核发 2026-09-23）

第 2 条候选（loupan_id=3 风华锦澜里）因该楼盘 `deleted=1` 被正确过滤，故 1 条符合数据实际。
