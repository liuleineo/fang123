# 2026-10-12 素材视频上传长时间卡在 99%

## 现象

`https://hangfang123.com/admin/medias` 上传视频素材，进度条长时间停在 99%。

## 根因分析

上传链路为：**浏览器 → Nginx → Spring(Tomcat) 落盘 → 后端转存腾讯云 COS**，共两次完整传输：

1. `admin/src/views/LoupanMediaManage.vue` 的 `uploadRequest()` 在 `onUploadProgress` 里把进度 `Math.min(99, ...)` 封顶，
   只有服务端返回后才由 `t-upload` 置为 100%。所以"卡在 99%"= 体数据已发完，**正在等服务端返回**。
2. 服务端返回前要完成：Nginx 收完 body（默认 `proxy_request_buffering on`，先落盘）→ Tomcat 解析 multipart 到临时文件 →
   `CosService.uploadFile()` 把文件 PUT 到 COS。第 3 步受**服务器出口带宽**限制，500MB 视频可能需十几分钟。
3. 两段传输串行，都吃服务器上行带宽；前端固定 20 分钟超时（`1200000ms`）在小带宽场景下可能被中途掐断。
4. Nginx `proxy_read_timeout` 若仍为默认/600s，后端转存耗时超过该值会以 **504** 切断（前端表现为 99% 后失败）。

## 改动

### 1. `backend/src/main/java/com/fang123/service/CosService.java`

- 新增 `TransferManager`（分片阈值 20MB、分片大小 10MB、并发 8 线程），**>20MB 的文件走分片并发上传**，
  替代原来的单连接单次 PUT，能明显提升大视频吞吐。
- 分片上传前把 `MultipartFile` 落到本地临时文件（分片要求内容可随机读取，MultipartFile 的流不可重置），上传完删除。
- `ClientConfig` 显式设置 `connectionTimeout=30s`、`socketTimeout=120s`（SDK 默认 50s）。
- 上传前后打印 INFO 日志：`COS upload start/done: key, size, mode, cost, avg=xx MB/s` / 失败时 `COS upload failed: ... cost=xxms`，
  便于直接判断瓶颈是"服务器→COS 带宽"还是其他环节。

### 2. `admin/src/views/LoupanMediaManage.vue`

- 上传控件下方新增阶段提示：进度条封顶后显示「文件传输完成，正在上传至云存储…（已等待 N 秒）」，每秒钟刷新，
  避免用户误以为卡死；成功/失败/移除时清理（`onUnmounted` 兜底）。
- 视频超时由固定 20 分钟改为**按体积动态计算**：`min(40min, max(20min, ceil(sizeMB) * 4s))`，500MB ≈ 33 分钟。

### 3. `README.md`

Nginx 示例更新：`client_body_timeout 1800s`、`proxy_read_timeout 1800s`、`proxy_send_timeout 1800s`、
`proxy_request_buffering off`（不缓存请求体，避免大文件多落一次盘）。

## 验证建议

1. 部署新 jar + admin dist，重启后端。
2. 上传同一视频，观察阶段提示是否出现、总耗时多久。
3. 看后端日志 `COS upload done: ... cost=xxms, avg=xxMB/s`：
   - avg 若只有不到 1MB/s → 瓶颈是服务器出口带宽，建议后续改为**前端直传 COS（STS 临时密钥 + 分片）**，绕开服务器中转；
   - avg 正常（几 MB/s 以上）但总耗时仍长 → 说明卡在浏览器→服务器这段，同样指向服务器带宽。
