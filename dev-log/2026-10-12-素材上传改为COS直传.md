# 2026-10-12 素材上传改为浏览器直传 COS（附中转降级）

## 背景

上一步把大视频改成服务端分片并发转存 COS，但根本瓶颈仍在**服务器出口带宽**：
浏览器 → 服务器 → COS 是两段串行，500MB 视频要等两次上行，表现为进度条长时间停在 99%。

## 方案

前端**直传 COS**：后端只签发预签名 PUT 地址，浏览器直接把文件传到云存储。

| 对比项 | 服务器中转（原） | 浏览器直传（现） |
| --- | --- | --- |
| 传输段数 | 浏览器→服务器→COS（两段串行） | 浏览器→COS（一段） |
| 速度瓶颈 | 服务器出口带宽（通常 3-10Mbps） | 客户端上行带宽 |
| 服务器负载 | 收 500MB + 发 500MB | 仅签发一个 URL |
| 返回内容 | 需等服务端转存完才返回 url | 上传完立即拿到最终 url |

## 改动

### 1. 后端

- `backend/src/main/java/com/fang123/service/CosService.java`
  - 新增 `presignPut(folder, filename, contentType, size)`：生成对象 key（`folder/uuid.ext`）与
    预签名 PUT URL（有效期 600s），返回 `PresignInfo(key, uploadUrl, url)`。
    - 签名绑定 `Content-Type`，前端 PUT 必须带同一个 `Content-Type`；
    - 扩展名走**白名单**（jpg/jpeg/png/gif/webp/bmp/mp4/mov/webm/avi/mkv/m4v），
      桶是公共读，避免被用来托管任意类型文件；
    - 大于 500MB 直接拒绝。
  - 抽出 `buildPublicUrl(key)`、常量 `MAX_FILE_SIZE`（原 uploadFile 里的硬编码）。
- `backend/src/main/java/com/fang123/controller/LoupanMediaController.java`
  - 新增 `POST /api/admin/medias/presign`（body: `{filename, contentType, size}`）→
    `{key, uploadUrl, url}`；参数非法返回 400。
  - 原 `POST /api/admin/medias/upload` 保留，作为直传失败时的降级通道。

### 2. 前端 `admin/src/views/LoupanMediaManage.vue`

- 新增 `uploadDirectToCos()`：先取预签名地址，再用**裸 axios**（不能带 Authorization，否则签名校验失败）
  `PUT` 到 COS，带 `onUploadProgress` 真实进度。
- 新增 `uploadViaServer()`：原中转逻辑抽出。
- `uploadRequest()` 改为**直传优先、失败自动降级中转**（如 COS 未配 CORS、预签名失败时功能不中断，
  仅失去加速；降级会在 console 打印 `直传 COS 失败，回退服务器中转`）。
- 超时分别估算：直传按 ~0.5MB/s（10-30 分钟），中转按 ~0.25MB/s（20-40 分钟）。
- 导入 `axios`。

## 待办（必须在腾讯云控制台做，否则直传会被浏览器 CORS 拦截）

COS 控制台 → 存储桶 `neoimage-1251198067` → 安全管理 → 跨域访问 CORS 设置 → 添加规则：

- 来源 Origin：`https://hangfang123.com`（本地调试再加 `http://localhost:5173`）
- 操作 Methods：`PUT`、`POST`、`GET`、`HEAD`
- Allow-Headers：`*`
- Expose-Headers：`ETag`、`x-cos-request-id`
- 超时 Max-Age：`600`

> 上传 `video/mp4` 属于非简单请求，浏览器会先发 OPTIONS 预检，因此 **PUT 与 Allow-Headers 必须配**。
