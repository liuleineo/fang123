# 2026-11-18 户型 AI 新建：支持批量识别与批量录入

## 需求

`/admin/huxings` 的「AI 新建户型」支持批量识别和录入户型。典型输入是一张包含多个户型卡片的长截图（如「139㎡·B2-1-4室2厅2卫」列表）。**注意：户型图（平面图）不参与识别，也不录入户型图片字段。**

## 现状与问题

改造前虽有「多图 OCR → 提取 huxings 数组 → 勾选后循环 POST」的雏形，但存在四个问题：

1. prompt 未说明「一张图可能含多个户型卡片」，模型容易只返回第一个
2. prompt 未屏蔽户型平面图内部文字（房间名、3.6×4.2 尺寸标注、图例），会污染字段
3. 字段不可修改，识别错了只能录入后再去列表里改
4. 前端对每条户型逐个 `POST /admin/huxings`，9 条就是 9 次请求，失败无明细

## 改动

### 1. `dto/AiParseHuxingResult.java`

`HuxingFields` 新增 `insideAreaWithGift`（套内面积含赠送）。原实体与前端已有该字段，但 DTO 未定义，导致「套内122.2㎡ 97%（含赠送）」里的含赠送面积永远丢失。

### 2. `service/AiParseService.java` — 重写 `HUXING_PARSE_PROMPT`

新增/强化的规则：

- **多卡片拆分**：明确「一张图可能包含多个户型卡片，典型写法是『面积㎡·户型编号-几室几厅几卫』，每个卡片单独输出一条，严禁合并或只取第一个」
- **huxingName 规范**：优先取卡片上的编号（B2-1、C1-1），无编号时用「面积+房型」
- **面积口径**：`area` 取建筑面积；`insideArea` 只取套内数字（如 122.2）；「97%」这类得房率不得写入任何数字字段；「含赠送」的套内面积填入 `insideAreaWithGift`
- **忽略户型图文字**：房间名（主卧/次卧/客厅/餐厅/厨房/卫生间/阳台/书房）、尺寸标注（3.6×4.2、3900×4200）、开间进深、家具名、图例、指北针，一律不算户型字段
- **过滤评价标签**：畅舒/宽敞/豪华/舒适/良好/优秀/较亮/平晾/暂无/动线/空间/采光/通风 归入 tag 或忽略，不能当数值
- **禁止输出图片字段**：第 9 条明确「禁止输出任何图片、图片URL、户型图相关字段」

### 3. 新增 `dto/HuxingBatchCreateRequest.java` + `POST /api/admin/huxings/batch`

```json
{ "loupanId": 1, "huxings": [ { "huxingName": "B2-1", "area": 139, ... } ] }
```

- 一次请求保存多条，返回 `{created, failed, errors:[{index, huxingName, msg}]}`
- `toEntity()` 做字段白名单转换：`BigDecimal → Integer`（四舍五入）、`huxingName` 为空时用「面积㎡户型」兜底、`floorType` 默认 1、`isShowHouse` 默认 0
- **`huxingImage` / `standardHuxingImage` 强制置空**，AI 结果不会带入任何图片 URL，户型图由人工在列表中补充
- 单条异常不中断整批，失败明细回传前端

### 4. `admin/src/views/LoupanHuxingManage.vue`

- 上传上限 5 → **10 张**，tips 改为「一张长图可包含多个户型」
- 结果列表从「只读展示」改为**逐条可编辑**：户型名称、建筑面积、套内面积、室/厅/卫、标签均为输入框，直接改 `aiResult.huxings[i]`
- 新增「全选 / 取消全选」与「已选 N 个」计数
- 录入按钮改为调用批量接口，提示改为「批量录入选中户型 (N)」；失败时展示后端返回的逐条原因
- 结果区底部提示：「户型图不会被 AI 识别录入，保存后可在列表中逐条补充」
- 弹窗顶部说明同步更新
