# 2026-10-18 客户跟进信息流页面

## 需求

用户端「今日跟进进度」弹窗底部在「关闭提示」旁增加「跟进客户」按钮，点击进入新页面：
以信息流方式展示客户资料与跟进记录，上下滑动切换客户；页面底部固定「电话客户」「增加跟进」两个按钮。

## 入口

`web/src/views/Customers.vue` 弹窗底部按钮改为两个：

```
[ 关闭提示 ]  [ 跟进客户 ]   → router.push('/customer-feed')
```

## 新页面 `web/src/views/CustomerFeed.vue`

**路由**：`/customer-feed`，注册在 WebLayout 之外（全屏，避免顶部导航与底部占位干扰）。

**数据**
- `GET /user/customers?sortField=lastFollowUpTime&sortOrder=asc`，每页 20 条
  按「最久未跟进」排序（从未跟进的排最前），打开就是从最该联系的人开始；
- `GET /user/customers/{id}/follow-ups` 按需加载，缓存到 `followCache`，
  每次预加载「当前 + 下一位」，滑动时不出现空白；
- 滑到距末尾 3 个客户时自动预取下一页（无限流）。

**交互**
- 垂直信息流用原生 `scroll-snap-type: y mandatory` + 每屏 `scroll-snap-align: start`，
  触摸滑动/滚轮/上下键都是整屏吸附切换，无需自己算手势；
- 顶部悬浮栏显示 `当前序号 / 总客户数`，左上角返回；
- 滚动用 `requestAnimationFrame` 节流计算当前屏索引，仅切屏时触发预加载。

**每屏内容**
- 客户卡：头像、姓名、意向标签、共享标记、手机号、未跟进天数（≥7 天红色、≥3 天橙色）、需求备注；
- 跟进记录：最近 5 条（方式标签 + 时间 + 内容），超出显示「仅显示最近 5 条，共 N 条」；
  限制条数是为了让每屏内容不溢出，保证上下滑动始终能切换客户；
- 跟进图片：解析 `photos`（JSON 数组字符串，实测格式 `["https://...jpg"]`），
  以 56px 缩略图网格展示在内容下方，点击用 `t-image-viewer` 全屏预览（支持左右切换同一条记录的图片）；
- 底部提示当前可上滑/已到底。

**底部操作（固定）**
- 「电话客户」：统一使用 `tel:` 协议直接调起拨号（`window.location.href = tel:号码`），
  不做"桌面端复制号码"的降级——按使用要求，点击即拨号；号码为空时提示"该客户没有填写手机号"；
- 「增加跟进」：弹窗选择方式（电话/微信/到访/其他）+ 填写内容，提交
  `POST /user/customers/{id}/follow-ups`，成功后刷新该客户记录并同步卡片上的「最后跟进」，
  返回列表页时列表与今日跟进数会重新加载（页面未用 keep-alive，回来即刷新）。

## 问题修复：图片位置显示"图片无法显示"、页面布局错乱（同日）

**现象**：跟进图片区域出现"图片无法显示"占位，信息流几乎空白，无法上下滑动，底部按钮被挤到顶部。

**根因**（用 playwright 实测 DOM 定位）：
`t-image-viewer` 未打开时会在 DOM 中渲染一个 `.t-image-viewer__trigger` 块，高度 659px，
它作为 `.feed-page` 的 flex 子项抢走了全部剩余空间，导致 `.feed-scroller` 的 `clientHeight` 变成 0；
trigger 内部是一个空的 `t-image` 组件，于是显示"图片无法显示"占位文案。
图片本身没有问题（接口返回正常、URL 直连 200、原图 1600×1063 可加载）。

**修复**：
1. `t-image-viewer` 移出 `.feed-page`（模板根级第二个节点）+ `v-if="viewerVisible"` 条件渲染 + `@update:visible` 回写，任何情况下都不参与 flex 布局；
2. 缩略图改为显式 CSS 尺寸（`.follow-photo` 56×56 + object-fit: cover），不再依赖 Tailwind 工具类，避免按原图尺寸撑满一屏；
3. 去掉 `loading="lazy"`（在 scroll-snap + 内部滚动容器里可能永不触发加载）；
4. 每条跟进最多显示 6 张缩略图，超出显示 `+N`，防止刷屏；
5. 加载失败替换为透明占位，不出现裂图图标。

**实测结果**（playwright，登录态 localStorage 注入）：
```
.feed-scroller clientHeight = 659，每屏 slide 高度 = 659
.follow-photo = 56×56，naturalWidth = 1600（加载成功），页面无"图片无法显示"文案
打开预览 / 点击关闭后：clientHeight 仍为 659，viewer 正确卸载
滚动一屏：scrollTop=659，顶部序号 1/4 → 2/4
```

## 主题改为黑色（同日）

信息流页面整页深色化，不影响站点其它页面（样式全部限定在 `.feed-page` 作用域内）。

- 配色：页面底 `#0d0f13`、卡片 `#161a21`、描边 `#232833`、主文字 `#f2f4f7`、次文字 `#a9b1bd`；
- **在 `.feed-page` 上重定义 `--color-text-primary/secondary/tertiary/--color-primary`**，
  模板里已有的 `var(--color-*)` 自动跟随，不用逐处改类名；
- 硬编码浅色块逐个替换：备注区/跟进条目 `bg-[#F8FAFE]` → `bg-white/[0.045]`，标签/头像占位改半透明白/深蓝灰；
- 意向标签、未跟进天数改用带透明度的红/橙（`bg-red-500/15 text-red-400`），深色下不刺眼；
- 底部操作栏「电话客户」是 outline 按钮，默认白底黑字，用 `:deep(.t-button--variant-outline)` 改为透明底浅色描边；
- 增加跟进弹窗被 Teleport 到 body，普通 scoped 样式作用不到；给 `t-dialog` 加 `class="feed-dark-dialog"`，
  **类名落在弹窗外层容器而非 `.t-dialog` 本身**，所以背景必须写成后代选择器
  `:global(.feed-dark-dialog .t-dialog)`，同时覆盖 `--td-bg-color-container`；textarea 也一并深色化。

实测（playwright）：页面背景 `rgb(13,15,19)`、卡片 `rgb(22,26,33)`、正文 `rgb(242,244,247)`、
弹窗底 `rgb(22,26,33)`、标题白、textarea 深色；`feed-scroller` 高度仍为 659，布局未受影响。
