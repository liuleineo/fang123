# 2026-11-11 新盘信息列表按行政区排序

## 需求

`https://hangfang123.com/xinpanlist` 的数据按行政区排序（同一行政区聚在一起，按杭州官方区划顺序）。

## 实现

### 1. 后端：新增 `common/DistrictOrder.java`

行政区中文无法靠数据库 collation 排成官方顺序（字符序会得到「上城、临平、临安、余杭……」），因此用权重映射：

```java
HANGZHOU = ["上城区","拱墅区","西湖区","滨江区","萧山区",
            "余杭区","临平区","钱塘区","富阳区","临安区"]
```

- `weight(String)`：行政区 → 权重，未知/空值返回 10（排最后）；兼容「余杭」「余杭区」两种写法
- `sorted(List<String>)`：行政区下拉选项排序，未知项按字符序兜底
- `orderByClause(column, tail)`：生成 `ORDER BY CASE WHEN district LIKE '上城%' THEN 0 … ELSE 10 END, district, sort DESC, create_time DESC`
  - 用 `LIKE '上城%'` 而非等值，兼容数据带/不带「区」后缀
  - 列名做 `[A-Za-z0-9_]+` 校验，避免拼接注入

### 2. 后端：`LoupanPublicController#list` 新增可选参数

```
GET /api/public/loupans?...&orderByDistrict=true
```

- `orderByDistrict=true` → 走 `w.last(DistrictOrder.orderByClause("district", "sort DESC, create_time DESC"))`
- 不传（首页、地图找房、新盘等旧调用）→ 保持原 `sort DESC, create_time DESC`，**不影响其他页面**

### 3. 后端：`/api/public/loupan-filters` 行政区顺序同步

原 `distinct().sorted()` 改为 `DistrictOrder.sorted(...)`，保证下拉选项顺序与列表一致。

### 4. 前端：`web/src/views/XinpanList.vue`

```js
const params = { page: page.value, size: size.value, orderByDistrict: true }
```

### 5. 环境修复（非代码）

本地 dev 库 `loupan` 表缺 `advantage` / `disadvantage` 列，导致公开列表接口 500（`Unknown column 'advantage'`）。已执行：

```sql
ALTER TABLE loupan
  ADD COLUMN advantage text COMMENT '楼盘优点' AFTER view_support,
  ADD COLUMN disadvantage text COMMENT '楼盘缺点' AFTER advantage;
```

`schema.sql` 中本就有这两列，DDL 无需改动。

## 验证

临时插入 5 条不同行政区的测试数据（验证后已删除，真实数据恢复 2 条）：

| 接口 | 结果 |
| --- | --- |
| `/api/public/loupans?orderByDistrict=true&size=20` | 上城区 → 西湖区 → 余杭区 → 钱塘区 → 临安区 → 空值（最后） |
| 同上 `page=2&size=3` | 钱塘区、钱塘区、临安区，接续第一页，`total=7` 正确（count 未被 ORDER BY 影响） |
| `/api/public/loupans?size=10`（不传参数） | 仍为 `sort DESC, create_time DESC`，行为不变 |
| `/api/public/loupan-filters` | `["上城区","西湖区","余杭区","钱塘区","临安区"]` |

前端页面（Vite 4000 + 真实后端 8090，Playwright 读取表格）行顺序与接口一致：
`上城区 | 西湖区 | 余杭区 | 钱塘区 | 钱塘区 | 临安区 | -`（空行政区显示 `-`）。
